# BO:IM

**안 보이던 기업을 데이터로 증명합니다.**

BO:IM(보임)은 뉴스·특허·채용 정보가 적어 외부에 잘 드러나지 않는 B2B 제조기업의 실제 성장을, 거래명세서 같은 내부 문서와 함께 분석해 증명하는 기업 성장 진단 서비스입니다.

🔗 **[Live Demo](https://boim-hazel.vercel.app)**

---

## 왜 필요한가

기존 신용평가·기업 조회 서비스는 뉴스, 특허, 공시 같은 **공개 정보**를 중심으로 기업을 평가합니다. 그런데 실제로는:

- 언론 노출이 없어도 거래처가 꾸준히 늘고 있는 기업
- 특허가 없어도 반복 거래로 안정적인 매출을 내는 기업

처럼, **외부에는 안 보이지만 내부적으로는 성장하고 있는 기업**이 적지 않습니다. BO:IM은 공개 데이터(외부 가시성)와 기업이 직접 제공하는 내부 거래 문서(성장 신호)를 나란히 놓고, 공개 정보만으로는 놓치는 성장을 데이터로 보여줍니다.

> 본 서비스는 신용평가가 아닌 AI 기반 성장 진단 참고 자료입니다.

## 세 가지 원칙

이 서비스가 다른 문서 분석 서비스와 갈라지는 지점입니다.

**1. 문서가 기기를 떠나지 않습니다.** 거래명세서에는 사업자번호·주소·계좌번호·직인이 들어 있습니다. 인식부터 지표 계산까지 전부 브라우저 안에서 끝나고, 파일은 서버로 올라가지 않습니다. → [자세히](#문서가-기기를-떠나지-않습니다)

**2. 판단은 코드가 하고, LLM은 문장만 씁니다.** 어떤 지표를 볼지, 어떻게 셀지, 무엇을 긍정/주의로 볼지는 전부 `lib/signals.ts`가 정합니다. LLM에는 이미 끝난 판정만 넘어갑니다. 그래서 같은 데이터에는 항상 같은 진단이 나옵니다.

**3. 모르는 것은 모른다고 말합니다.** 외부 API가 대답하지 않으면 "0건"이 아니라 "확인 불가"로 적고, 그 지표는 점수 계산에서 아예 뺍니다. 문서 없이 예시 데이터로 계산했다면 화면과 진단서에 그대로 밝힙니다. → [자세히](#숫자를-다루는-규칙)

## 진단 과정

| STEP | 화면 | 내용 |
| --- | --- | --- |
| 1 | 기업 검색 | DART에 등록된 11만 8천여 법인에서 진단할 기업 검색 |
| 2 | 외부 가시성 확인 | 뉴스·특허·고용·공시로 공개 정보 수준 측정 |
| 3 | 내부 문서 업로드 | 거래명세서·세금계산서·발주서 등 6종 (거래명세서 하나만 있어도 진단됨) |
| 3.5 | 분석 진행 | 업로드한 문서를 브라우저 안에서 OCR·파싱 |
| 4 | AI 분석 결과 확인 | 신뢰도가 낮은 항목만 사용자가 직접 확인·수정 |
| 5 | 성장 신호 · 비교 | 내부 신호 6개를 계산해 외부 가시성과 나란히 비교 |
| 6 | 성장 리포트 | 종합 진단서를 확인·인쇄 |

문서가 없어도 샘플 문서로 전체 과정을 돌려볼 수 있습니다. 샘플도 실제 엑셀 파일이라 손으로 올린 파일과 같은 인식 경로를 그대로 탑니다.

## 무엇을 재는가

### 외부 가시성 (0~100점)

공개 정보에 이 기업의 활동이 얼마나 남아 있는지 봅니다. **성장성 점수가 아니라 "밖에서 얼마나 보이는가"입니다.**

| 축 | 출처 | 배점 | 만점 기준 |
| --- | --- | --- | --- |
| 뉴스 | 네이버 뉴스 검색 | 35 | 500건 |
| 특허 | KIPRIS 출원인 검색 | 25 | 50건 |
| 공시 | DART 공시검색 (최근 1년) | 25 | 30건 |
| 고용 규모 | 국민연금 가입 사업장 (공공데이터포털) | 15 | 100명 |

고용 규모만 건수가 아니라 사람 수입니다. 원래 이 축은 채용공고 건수였는데, 공고는 회사가 안 올리기로 하면 그냥 0이 됩니다. 이 서비스가 다루는 B2B 제조 중소기업은 대부분 공개 채용을 하지 않아 축 하나가 통째로 죽어 있었습니다. 국민연금 가입자 수는 의무 신고의 결과라 홍보를 안 하는 회사에도 남고, 월 단위로 쌓여 규모와 함께 증감까지 읽힙니다. 다만 가입자 3인 이상 법인사업장만 자료에 포함되므로, **찾지 못한 회사를 0명으로 적지 않고 "확인 불가"로 둡니다.**

건수를 그대로 더하지 않고 로그로 눌러 0~1 비율로 바꾼 뒤 배점을 곱합니다. 실제 API를 붙이자 뉴스가 수십만 건까지 나와서, 단순 가중합으로는 점수가 0 아니면 100인 이진값이 됐기 때문입니다. **확인하지 못한 축은 배점에서 통째로 빼고 남은 배점으로 100점을 만듭니다** — 0점으로 세면 "못 불렀다"가 "없다"와 같은 감점이 됩니다.

공시를 넣은 이유가 이 서비스의 문제의식과 맞닿아 있습니다. 뉴스·특허·채용은 전부 "밖에서 얼마나 보이나"를 재기 때문에 홍보를 안 하는 회사는 전부 0으로 깔립니다. 공시는 회사가 의무적으로 남긴 기록이라 검색 노출과 무관하게 남고, **홍보를 안 해서 안 보이는 회사와 실제로 활동이 없는 회사를 갈라줍니다.**

### 내부 성장 신호 (6개)

업로드한 거래 문서에서 계산합니다.

| 신호 | 긍정 기준 |
| --- | --- |
| 거래처 증가율 | 이전 기간보다 늘면 |
| 거래금액 증가율 | 이전 기간보다 늘면 |
| 반복거래율 | 50% 이상 |
| 최대 거래처 집중도 | 25% 미만 |
| 거래 지속성 | 70% 이상 |
| 최근 추세 | 직전 구간보다 늘면 |

여섯 신호 중 긍정 판정 개수로 성장 잠재력 등급을 매깁니다. **A**(5개 이상) · **B+**(4개) · **B**(2~3개) · **C**(1개 이하), 그리고 **평가 가능한 신호가 3개 미만이면 등급을 만들지 않습니다.**

마지막 규칙이 중요합니다. 비율만 보고 표본을 보지 않으면 데이터가 없을수록 점수가 좋아집니다. 거래가 0건이면 집중도 0%로 "여러 거래처에 분산됨", 1건이면 지속성 100%로 "꾸준히 이어짐"이 되어 아무 자료도 없는 기업이 B등급을 받습니다. 이 판정이 그대로 LLM 프롬프트로 넘어가면 읽는 쪽에서 걸러낼 방법이 없어, 계산 단계에서 막습니다(`lib/signals.test.ts`).

## 문서가 기기를 떠나지 않습니다

```
문서 파일  ──(기기 밖으로 나가지 않음)
   │
   ├─ 브라우저에서 OCR·파싱      PaddleOCR PP-OCRv5 한국어 모델(ONNX)
   │                             onnxruntime-web / pdf.js / xlsx 직접 파싱
   ├─ 브라우저에서 지표 계산      lib/signals.ts — 거래처 증가율·재구매율·집중도 등
   │                             무엇을 긍정/주의로 볼지까지 코드가 정한다
   └─ 사용자가 버튼을 눌렀을 때만
      계산된 비율과 판정만 전송  ──▶ 서버 ──▶ LLM
```

LLM으로 나가는 본문 전체는 이런 모양입니다. 파일도, 원문 텍스트도, 거래처 이름도, 금액도 들어 있지 않습니다.

```json
{ "transactionCount": 21, "positiveCount": 5, "cautionCount": 0,
  "activityLevel": "활발",
  "signals": [
    { "label": "거래처 증가율", "value": 66.7, "tone": "긍정", "note": "신규 거래처 확대 신호" },
    { "label": "최대 거래처 집중도", "value": 34.8, "tone": "보통", "note": "한 거래처 비중이 다소 높음" }
  ] }
```

- **기본값은 호출하지 않음입니다.** 사용자가 버튼을 눌러야 나갑니다. 무엇이 전송되는지 버튼 옆에 적어 두었습니다.
- **거래처명은 마스킹합니다.** 프롬프트에는 `"최대 거래처"`로만 넣고, 응답을 화면에 보여줄 때 브라우저에서 실명으로 되돌립니다. LLM은 실제 거래처명을 한 번도 보지 않습니다.
- **자유 문자열이 프롬프트로 직행하지 않습니다.** 서버가 지표 이름과 판정을 허용 목록으로 거르고 숫자는 범위를 제한합니다.

서버로 가는 것은 기업 고유번호뿐이고, 그것으로 뉴스·특허·고용·공시 같은 **공개** 정보만 조회합니다.

## 숫자를 다루는 규칙

화면에 뜨는 숫자가 판단의 근거가 되므로, 확실한 것과 그렇지 않은 것을 구분합니다.

**정확 일치만 씁니다.** 기업명을 부분 일치로 찾으면 "한빛정밀"에 전혀 다른 법인인 "한빛"이 걸리고, 그 회사의 공시 건수가 우리 회사 것으로 표시됩니다. 못 찾으면 못 찾았다고 합니다.

**추론하지 않고 실제로 셉니다.** 특허 검색은 총건수를 그대로 믿으면 안 됩니다. 포스코는 총 52,561건이 잡히지만 뒷부분은 이름이 다른 계열사(포스코플랜텍 → "주식회사 플랜텍")이고, 한빛정밀은 12건이 잡히지만 전부 무관한 출원인입니다. 그래서 300건까지는 페이지를 넘겨가며 전부 읽어 세고, 넘으면 **읽은 만큼만 "N건 이상"**으로 적습니다.

**확인 못 한 것은 확인 못 했다고 적습니다.** 외부 API가 응답하지 않으면 화면은 "0건" 대신 "확인 불가", 진단서는 "남아 있지 않습니다" 대신 "확인하지 못했습니다"라고 쓰고, LLM 프롬프트에도 숫자 대신 확인 불가로 넘깁니다.

**예시 데이터는 예시라고 적습니다.** 문서를 올리지 않으면 내부 신호는 예시 데이터로 계산되는데, 화면과 진단서 양쪽에 그 사실과 근거 문서 목록(없으면 "붙임 없음")을 표시합니다.

## 기술 스택

- **Framework**: Next.js 16 (App Router, Turbopack)
- **Language**: TypeScript
- **Styling**: Tailwind CSS 4
- **문서 인식**: PaddleOCR PP-OCRv5 한국어 모델(ONNX) + onnxruntime-web — 브라우저에서 실행
- **LLM**: OpenAI `gpt-5-nano` — 해석 문장 생성에만 사용
- **외부 데이터**: DART · 네이버 뉴스 · KIPRIS · 사람인
- **Hosting**: Vercel

프론트엔드 페이지와 API가 하나의 Next.js 앱에서 함께 서빙되며, 서버 컴포넌트는 API를 다시 호출하지 않고 `lib/engine.ts`의 데이터 계층을 직접 사용합니다.

## API

| Endpoint | 설명 |
| --- | --- |
| `GET /api/health` | 서버 상태 확인 |
| `GET /api/companies?q={기업명}` | DART 기업 목록에서 검색 |
| `GET /api/visibility?company={고유번호}` | 뉴스·특허·고용·공시 기반 외부 가시성 점수 |
| `GET /api/signals?company={고유번호}` | 내부 성장 신호 (예시 데이터 기준) |
| `POST /api/signals-insight` | 내부 신호 해석 문장 (LLM) |
| `POST /api/diagnosis` | 진단서 종합 의견 (LLM) |

CORS는 배포 도메인(`https://boim-hazel.vercel.app`)에만 열려 있습니다.

## 로컬 실행

```bash
npm install
npm run dev
```

`http://localhost:3000`에서 확인할 수 있습니다. `npm run dev`는 pdf.js 자산 복사와 DART 기업 목록 인덱스 생성을 먼저 실행합니다.

```bash
npm run build   # 프로덕션 빌드
npm run lint    # 린트 검사
npm test        # 성장 신호 계산 테스트
```

### 환경변수

`.env.local`에 넣습니다. **키가 없어도 앱은 동작합니다** — 해당 지표만 예시 데이터로 대체되거나 "확인 불가"로 표시됩니다.

| 변수 | 용도 |
| --- | --- |
| `DART_SEARCH_KEY` | 기업 검색·공시 건수 (OpenDART) |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | 뉴스 건수 (네이버 클라우드 플랫폼 API Gateway) |
| `KIPRIS_SERVICE_KEY` | 특허 건수 (KIPRIS Plus) |
| `KOOKMIN_API_KEY` | 국민연금 가입자 수 (공공데이터포털) |
| `OPENAI_API_KEY` | 해석 문장 생성 |

Vercel에 배포할 때는 **프로젝트 설정의 환경변수에 따로 등록해야 합니다.** 로컬 `.env.local`은 배포에 반영되지 않습니다.

## 배포

Vercel에 연동되어 `main` 브랜치에 머지되면 자동 배포됩니다.

DART 기업 목록(11만 8천여 건)은 빌드 시점에 인덱스로 구워 배포물에 포함됩니다. 서버리스는 콜드스타트마다 모듈 캐시가 비기 때문에, 런타임에 3.6MB짜리 목록을 매번 받으면 기업 검색이 30초씩 걸립니다. 이 인덱스는 저장소에도 커밋돼 있어, 빌드 중 OpenDART가 점검이더라도 검색이 멈추지 않습니다.

## 유의사항

- 기업 검색과 외부 가시성(뉴스·특허·고용·공시)은 실제 공개 데이터를 조회합니다. 내부 거래 데이터는 문서를 올리지 않으면 예시 데이터로 계산되며, 화면과 진단서에 그 사실을 표시합니다.
- 현재 시연 버전입니다. 문서는 서버로 전송되지 않지만, 실제 기업의 민감한 문서는 올리지 않는 편을 권합니다.
- 본 서비스는 신용평가 결과가 아닌 AI 기반 성장 진단 참고 자료입니다.
